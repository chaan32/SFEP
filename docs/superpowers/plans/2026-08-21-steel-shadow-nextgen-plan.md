# Steel Shadow Validation and Next-Generation Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an append-only future Shadow validation workflow and a HOLDOUT-independent next-generation steel quality model laboratory without falsely treating historical data as new evidence.

**Architecture:** `shadow_contract.py` owns schemas, hashes, timestamps, and atomic storage; `run_shadow.py` owns registry, scoring, delayed-label settlement, evaluation, and status; `train_nextgen.py` owns pre-2025-09-01 feature engineering, grouped OOF model selection, calibration, and frozen artifacts. Historical HOLDOUT is allowed only in a physically separate non-independent dry run, while real Shadow evidence is written under `shadow_output/`.

**Tech Stack:** Python 3.14, pandas 3.0.1, NumPy 2.4.2, scikit-learn 1.9.0, SciPy 1.17.1, joblib 1.5.3, `unittest`.

**Spec:** `docs/superpowers/specs/2026-08-21-steel-shadow-nextgen-design.md`

## Global Constraints

- The positive class is exactly `judge=불량`; classifier class order must be `[0, 1]`.
- Feature schema and candidate selection may use only `TRAIN` plus `VALIDATION` rows with `ap_date < 2025-09-01`; HOLDOUT must not affect schema, folds, candidates, thresholds, or calibration.
- Shadow Feature Batches must reject `judge`, `ap_date`, `label_finalized_at`, `dataset_split`, and all other `ap_*` columns.
- Shadow prediction timestamps are generated by the scoring process in timezone-aware UTC; they are never trusted from input.
- Writes are append-only and atomic; JSON uses `allow_nan=False`, and CSV uses UTF-8-SIG.
- No command may set `deployment_eligible=true`; successful metrics can only produce `HUMAN_REVIEW_CANDIDATE`.
- Use only packages already pinned in `training/steel/requirements.txt`.
- Because Git metadata currently hangs in this workspace, each commit step must first run the scoped `git status` command with a 10-second operational limit; if Git remains unavailable, record `COMMIT_SKIPPED_GIT_UNAVAILABLE` and continue without staging unrelated user files.

def _utc_timestamp(value: object, *, field: str) -> pd.Timestamp:
    timestamp = pd.Timestamp(value)
    if timestamp.tzinfo is None:
        raise ValueError(f"{field} must be timezone-aware")
    return timestamp.tz_convert("UTC")

def make_batch_id(source_sha256: str, generated_at: pd.Timestamp) -> str:
    utc = _utc_timestamp(generated_at, field="generated_at")
    return f"{utc.strftime('%Y%m%dT%H%M%S%fZ')}-{source_sha256[:12]}"
